# Live class standard operating procedure

**Scope:** Pakish Institute Academy (`academy.pakish.org`)  
**Timezone:** Asia/Karachi (PKT)  
**Pilot course:** AI Productivity & Automation (private)

## Prerequisites

- Private course created and instructor added as contributor.
- Learners enrolled via verified admission workflow.
- Meeting platform account confirmed by owner (not provisioned in Prompt 13).

## Before session

1. Academic admin confirms roster in LearnHouse (enrollment trail).
2. Instructor opens live-session activity in module 4 (placeholder fields).
3. Owner or instructor pastes meeting link **only** into the private activity (never public website).
4. Backup host identified and recorded in activity metadata.
5. Attendance owner assigned (name unconfirmed until owner input).

## During session

1. Start meeting from owner-approved account.
2. Record only if learner consent policy allows (policy unconfirmed).
3. Note attendance in external sheet or LearnHouse notes — native attendance tool not verified.

## After session

1. Upload replay to **approved durable storage** when available (currently unpopulated).
2. Update recorded-lesson template with version/date and resource links.
3. Link replay in the live-session activity replay field.
4. Notify enrolled learners through approved channel (manual; no auto-email in pilot).

## Reschedule / cancel

- Minimum 24 hours notice when possible.
- Instructor or attendance owner updates live-session activity and sends one approved reschedule message.
- Document reason in course update or internal ops log.

## Failure / backup

- Backup host starts meeting if primary unavailable.
- If platform outage: reschedule; do not publish ad-hoc public links on main website.
- Database rollback: see `PILOT_ACCEPTANCE_REPORT.md` backup section.

## Prompt 13 readiness

- Live-session **information area** exists in pilot course (markdown template).
- Meeting URL, schedule, and hosts remain **placeholders** — owner input required before production cohort.
